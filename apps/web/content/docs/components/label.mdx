## Usage

```tsx
import { Label } from "@/components/ui/label";

<Label htmlFor="phone">Phone number</Label>
<Input id="phone" />
```

## For a phone number

A phone number usually needs a country. The demo at the top pairs a `Label` with [Phone input](/docs/components/phone-input), which has a searchable country dropdown. Give the number field the label's `id`, as with any input.

```tsx
<Label htmlFor="phone">Phone number</Label>
<PhoneInput id="phone" name="phone" />
```

For a plain local number, use a normal [Input](/docs/components/input) with `type="tel"` instead.

## Looks

<Preview>
  <Demo name="label-looks" />
</Preview>

- **`required`** adds a red asterisk. It is decorative, so also put `required` on the input itself; that is what assistive technology reads.
- **`optional`** adds "(optional)" after the text. It is part of the label, so screen readers read it too. Marking the few optional fields is often clearer than starring every required one.
- **`variant`**: `default`, `caps` (small spaced capitals in the same font, for dense forms) or `muted`.
- **`size`**: `sm`, `md` or `lg`. Match it to the input's size.

```tsx
<Label htmlFor="name" required>Full name</Label>
<Label htmlFor="nick" optional>Nickname</Label>
<Label htmlFor="phone" variant="caps" size="sm">Phone number</Label>
```

## Accessibility

- It is a native `<label>`, so clicking it focuses the control and screen readers announce it as the control's name.
- A label is required for every input. A placeholder is not a label.
- The asterisk is hidden from assistive technology; the control's own `required` attribute carries the meaning. Don't rely on colour alone: the asterisk is a shape, and "(optional)" is text.

## Tokens used

`--foreground`, `--muted-foreground`, `--danger`.

## Known limitations

- It does not check that it is associated with a control; that is up to you.
