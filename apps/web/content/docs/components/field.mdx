Use `Field` around any form control to get a visible label, optional helper text and an error message, with the `id` and `aria-describedby` wiring done for you.

## Installation

<InstallTabs name="field" />

Field does not depend on a specific control. Install [Input](/docs/components/input) or [Textarea](/docs/components/textarea) alongside it.

## Usage

`Field` takes a function as its child and gives it the props to spread on your control. This keeps the wiring explicit and works in Server Components.

```tsx
import { Field } from "@/components/ui/field";
import { Input } from "@/components/ui/input";

<Field label="Email" hint="We only use it for receipts." error={errors.email}>
  {(control) => <Input type="email" name="email" {...control} />}
</Field>
```

  ]}
/>

`Field` also accepts native `<div>` props, which are spread on the wrapper.

## Accessibility

- The label is a native `<label for>` pointing at the control's generated id (`useId`, so it is stable across server and client).
- Hint and error are linked with `aria-describedby`; the error also uses `role="alert"` so it is announced when it appears.
- The control gets `aria-invalid` only while there is an error.
- Errors are text, never colour alone.

## Tokens used

`--foreground`, `--muted-foreground`, `--danger`.

## Known limitations

- It wires one control. Groups such as radio sets need a `fieldset` and `legend`, which will come with those components.
- It does not validate; pass your own `error`.
