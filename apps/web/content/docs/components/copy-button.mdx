Use `CopyButton` next to something users will paste elsewhere: a link, an install command, an account number. It says "Copied" when it worked and "Copy failed" when it didn't.

## Installation

<InstallTabs name="copy-button" />

This also installs [Button](/docs/components/button), which it is built on.

## Usage

```tsx
import { CopyButton } from "@/components/ui/copy-button";

<CopyButton value="https://zuri.dev/r/button.json" label="Copy link" />
<CopyButton value={command} iconOnly label="Copy command" />
```

## Props

`CopyButton` takes the same props as [Button](/docs/components/button) (variant, size, shape and the rest), except `onClick`, `children` and `loading`.

## Accessibility

- It is a native button, so Enter and Space work.
- The result is announced through a live region (`role="status"`) that is always on the page, so screen readers pick it up. In icon-only mode the accessible name stays the same and only the live region changes.
- Failure is reported, never hidden. The clipboard needs a secure context (HTTPS or localhost) and a user action.
- Under `prefers-reduced-motion`, the button's press animation is off.

## Tokens used

The same as Button.

## Known limitations

- It uses the asynchronous Clipboard API only. There is no fallback for old browsers or insecure pages; it reports failure instead.
- It is a client component, because it holds the copied state.
- Don't copy secrets such as card numbers or PINs; payment components in Zuri never put those on the clipboard.
